### 2.1 架构决策记录（关键取舍）

**决定**：不逆向桌面端私有 WebSocket RPC 协议，改为自建 PC 侧零依赖 Node 网关 + 复用官方 `headless` profile。

**证据支撑**：
1. 桌面端 Web GUI 对**所有**路径（含 `/api/*`、`/`）在回环地址上返回 `401`，认证依赖浏览器会话授权（凭据库中 `client-connection/browser-session` 为一次性授权记录），第三方客户端难以稳定复用；
2. 桌面端为 `0.2.0-rc.2`，而对外可分发的 CLI 为 `0.1.0-rc.7`，两者凭据格式**不兼容**（rc.7 的 `credentials-local` 要求 `.credentials.yaml` 为「引用→字符串」的扁平映射，rc.2 写的是结构化文档；复用主 home 会直接启动失败并报 `the value for "version" ... must be a string`）；
3. `headless` profile 提供稳定 CLI 契约：`--profile headless "<任务>"`，退出码 0/非 0，stdout 为最终答复，**不监听任何端口**，天然适合作为执行后端。

**代价**：远程任务与桌面端 GUI 会话相互独立（不共享会话历史）；这是可接受的，且避免污染用户正在使用的 GUI 会话。

### 3.5 关于第 6 项（已知兼容性说明，非缺陷）

裸 socket 抓取服务器实际发出的字节，确认网关**完整发送**了：

```
HTTP/1.1 413 Payload Too Large
Connection: close

{"error":{"code":"payload_too_large","message":"请求体超过上限 1048576 字节"}}
```

之后连接被重置（`ECONNRESET`）——网关按 Content-Length 预检后声明 `Connection: close` 并关闭套接字，而客户端此时仍在推送剩余 ~2 MB 数据。影响面：

| 客户端 | 表现 |
|---|---|
| `HttpClient`（逐块流式写，接近 Android OkHttp 行为） | ✅ 正确读到 `413` 与 JSON 体 |
| 裸 socket | ✅ 完整收到 413 + 响应体，随后 `ECONNRESET` |
| `HttpWebRequest`（先写满 2 MB 缓冲再读响应） | ⚠️ 抛"基础连接已经关闭"，拿不到响应体 |

**裁定：可用性影响极低，不计为阻断性缺陷。** ① 超过 1 MiB 的请求体属异常路径；② 目标客户端是 Android OkHttp，行为与已通过的 `HttpClient` 一致；③ 服务端语义正确。

## 4. 缺陷登记（验收阶段发现）

### 4.1 B-01：点击按钮无任何用户可见反馈（已定位并修复）

| 项 | 内容 |
|---|---|
| 发现方式 | Lead 在真实模拟器上按用户路径操作：填地址 → 点「测试连接」/「配对并保存」 |
| 现象 | 按钮有点击涟漪，但**既无提示、也无请求到达网关**；界面完全无变化 |
| Lead 初步判定 | 曾误判为"事件层未响应"，并据此要求实现者排查（结论见下，已修正） |
| **真因**（android-dev 定位，Lead 复核确认） | `ApiClient` 使用 OkHttp **同步**调用，而 ViewModel 运行在 `viewModelScope`（`Dispatchers.Main.immediate`）→ 点击后在**主线程**发起网络，抛出 `NetworkOnMainThreadException`，异常被 `runCatching` 吞进 `Result`，因此**既没有网络请求也没有用户可见反馈** |
| 定级 | **高**（功能性阻断：首次配对完全不可用） |

### 4.3 经验教训（已固化进文档）

1. **`runCatching` 不得静默**：捕获后若不产生用户可见反馈或日志，会把"功能性故障"伪装成"按钮没反应"，显著拉长定位时间（B-01 的直接教训）。
2. **改了代码必须重启守护进程**：判断方法为「进程 StartTime 早于源文件 LastWriteTime 即为旧进程」（D-01 的根因）。
3. **Windows PowerShell 5.1 的两个编码坑**：① `.ps1` 必须 UTF-8 **with BOM**；② `Invoke-RestMethod -Body <string>` 与非显式 UTF-8 的 `Get-Content -Raw` 都会按 ANSI/GBK 处理，中文必乱（D-02/D-08/D-09）。读取 `uiautomator dump` 等 UTF-8 文本必须用 `[System.IO.File]::ReadAllText($p, [Text.UTF8Encoding]::new($false))`。
4. **UI 自动化不得硬编码坐标**：明文 HTTP 提示卡会在填入 `http://` 地址后插入，使下方控件整体下移约 **280 px**；必须每次重新 dump 取 bounds。

**关键修复（使 D/E 从 FAIL → PASS）**：

1. **手机模拟器的断线重连缺陷（ops-doc 自查发现并修复）**：`WebSocketClient` 的 `socket.on('error')`
   只置 `closed` 并回调 `onError`，**没有触发 `onClose`** → 中继被杀（ECONNRESET）时上层收不到「连接已断」，
   既不重连也不报错，请求永远返回「隧道未连接」。修复：error 路径同样触发 `onClose`；心跳死链走同一路径；
   `#onClosed` 幂等化避免重复计时器。
2. **事件文件锁缺陷（同上）**：判据 D/E 的断言曾因 Node 长连接 `createWriteStream` 独占事件文件而假失败；
   改为 `appendFileSync` + PowerShell 侧 `FileShare.ReadWrite` 回退。
3. **`Wait-JsonLineMatch` 的 JSON 匹配缺陷**：`[string]$pscustomobject` 不是 JSON，`'"ok":true'` 永不匹配 → 改为对
   `ConvertTo-JsonText` 结果匹配（否则 D/E 会一直误报「没有任何成功请求」）。

**心跳 P0（已修复，2026-10-08 收尾复核）**：中继 `heartbeat.timeoutMs == intervalMs == 30000`
（`lib/tunnel.mjs:929-947` 用 `idle > timeoutMs` 判死链）导致 home 隧道每约 31s 被误杀一次
（日志 `心跳超时（3000Xms 无任何帧）` → `home 隧道下线（reason=timeout）`，网关 `reconnects` 随之增长）。
契约 §3.1 语义应为「发出 ping 后 30s 内无 pong 才判死链」。客户端重连已能自愈，但该抖动会降低稳定性，
且曾造成 `pair/claim` 偶发 `503 home_offline`。**建议**：`heartbeat.timeoutMs` 改为 `intervalMs × 3` 并加回归用例。
