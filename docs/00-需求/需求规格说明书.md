## 1. 背景与目标

### 1.1 一句话目标

用户**人不在 PC 前**时，用手机把任务下发给家里/公司的 Windows 电脑，PC 上 DSH 自动执行，过程与结果实时回传手机。

### 1.2 现状痛点

| # | 痛点 | 现状 |
|---|---|---|
| P1 | 桌面端 Web GUI 只监听 `127.0.0.1:19387`，离开本机就打不开 | 人在外面完全无法发起任务 |
| P2 | 桌面端凭据走「DeepSeek 账号平台」**设备授权**（内部授权），第三方客户端无法直接复用 | 想写个手机 App 直连桌面端，拿不到合法凭据 → 只能走本机 CLI |
| P3 | 桌面端与渲染进程之间是**私有 WebSocket RPC**，无公开协议文档 | 逆向实现会随版本升级失效，维护成本不可控 |
| P4 | 长时间任务（跑测试、批量改文件）需要几十秒到几十分钟 | 需要「随时看进度、随时取消」，而不是死等一个响应 |

### 1.3 解决思路（与已验证事实对齐）

| 决策 | 内容 | 依据 |
|---|---|---|
| D1 | 用官方 `dsh` CLI `0.1.0-rc.7` 的 **headless profile** 作为远程执行引擎：`node <bin.js> --profile headless "<任务文本>"`，独立 `DSH_HOME`、独立 session，退出码 `0` 表示成功 | 已实测：一条「写文件并回答 DONE」的任务 **2.6 秒**完成，文件真实落盘 |
| D2 | PC 端自建零第三方依赖 Node ESM 网关 `dsh-remote`（HTTP + SSE，默认 `8787`），为每个任务拉起独立 headless 会话 | 不逆向私有 RPC 协议（脆弱、随版本失效） |
| D3 | 手机端做原生 Android（Kotlin + Jetpack Compose）应用 `DshRemote` | 长连接保活、通知、断线续传需要原生能力 |
| D4 | 桌面端 `0.2.0-rc.2`（Electron，Web GUI `127.0.0.1:19387`）**不在远程链路内**，只作为同机 CLI 凭据来源的环境 | 桌面端仅本机可用，且凭据不可复用 |

## 4. 功能需求（FR-xx）

**约定**：状态值、字段名、错误码一律取自[API契约.md](../01-设计/API契约.md)；本表「契约映射」列即该需求的接口落点。

### 4.1 连通性与配对

| ID | 需求 | 优先级 | 契约映射 | 验收方法 |
|---|---|---|---|---|
| FR-01 | 网关必须提供**无需认证**的健康检查 `GET /api/v1/health`，返回 `ok`/`apiVersion`/`serverName`/`gatewayVersion`/`dshVersion`/`uptimeMs`/`activeTasks`/`queuedTasks`/`pairingOpen`/`authRequired`/`capabilities`；手机配置页用它探测连通性并显示服务器名与版本 | 必须 | 契约 §1 | TC-01, TC-02, TC-03 |
| FR-02 | 配对必须两步：PC **本机回环** `POST /api/v1/pair/open` 生成 6 位数字码（默认 5 分钟有效、一次性），手机 `POST /api/v1/pair/claim` 提交 `code`+`deviceName`+`deviceId` 换 `token`/`tokenId`/`serverName`/`expiresAt`；`deviceId` 必须匹配小写 UUID 正则（见 FR-28），不匹配返回 `400 bad_request` | 必须 | 契约 §2.1, §2.2, 裁定 A4 | TC-10, TC-11, TC-13, TC-19, TC-96 |
| FR-03 | 网关必须提供 `GET /api/v1/workspaces` 返回白名单 `workspaces[]`（`path`/`label`/`exists`）与 `default`，供手机首页选择工作区 | 必须 | 契约 §5 | TC-21 |
| FR-19 | 配对码错误/过期必须返回 `401 pairing_bad_code`；未开启配对必须返回 `403 pairing_closed`；`pair/open` **仅回环可达**（只接受 `127.0.0.1`/`::1`），非回环来源一律 `403 forbidden`，且**不引入**"本地管理口令"配置项 | 必须 | 契约 §2.1, 裁定 A1 | TC-14, TC-15 |

### 4.2 任务生命周期

| ID | 需求 | 优先级 | 契约映射 | 验收方法 |
|---|---|---|---|---|
| FR-04 | `POST /api/v1/tasks` 接受 `prompt`（必填）、`workspace`（必填，须落在白名单内）、`title`（可选，缺省取 prompt 前 40 字）、`model`（可选）、`reasoningEffort`（可选）、`timeoutSec`（可选，缺省 3600、上限 86400，**超上限返回 `400 bad_request`**，见裁定 A6），成功返回 `201` 与完整 Task 对象，初始 `status="queued"` | 必须 | 契约 §3.1, 裁定 A6 | TC-20, TC-22, TC-23, TC-27, TC-97 |
| FR-05 | 每个任务必须由**独立子进程 + 独立 DSH session** 执行：以 argv 数组 spawn `node <bin.js> --profile headless "<prompt>"`，cwd 为任务 workspace，`DSH_HOME` 为凭据目录；进程退出码 `0` 判 `succeeded`、非 `0` 判 `failed` 并写入可读 `error`，stdout 最终答复文本落入 `output` | 必须 | 契约 §3.1 状态机 | TC-24, TC-29, TC-41 |
| FR-06 | 状态机必须严格单向：`queued → running → succeeded \| failed \| canceled`；`queued`/`running` 为活动态，其余为终态 | 必须 | 契约 §0 | TC-28, TC-33 |
| FR-07 | `GET /api/v1/tasks/{id}` 返回 Task 对象，其中 `output` 为**当前累计的完整输出**（非增量） | 必须 | 契约 §3.3 | TC-34 |
| FR-08 | `GET /api/v1/tasks?status=active\|all&limit=50&cursor=<id>` 按 `createdAt` 倒序分页返回 `tasks[]` 与 `nextCursor` | 必须 | 契约 §3.2 | TC-37 |
| FR-09 | `POST /api/v1/tasks/{id}/cancel`：活动任务终止子进程与进程组并置 `canceled`，`queued` 任务直接出队并置 `canceled`，终态任务幂等返回原对象 | 必须 | 契约 §3.4 | TC-25, TC-26 |
| FR-11 | `DELETE /api/v1/tasks/{id}` 仅允许删除**终态**任务，成功返回 `204`；对活动态（`queued`/`running`）任务必须返回 `409 conflict` | 必须 | 契约 §3.5, 裁定 A7 | TC-38, TC-39, TC-98 |

### 4.2.1 输入校验与错误语义（裁定 A1~A7 落地）

| ID | 需求 | 优先级 | 契约映射 | 验收方法 |
|---|---|---|---|---|
| FR-28 | `pair/claim` 的 `deviceId` 必须匹配 `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$`（小写 UUID 文本）；不匹配返回 `400 bad_request`（客户端必须生成小写 UUID） | 必须 | 裁定 A4 | TC-96 |
| FR-29 | 任务删除的状态约束：终态 `204`；活动态 `409 conflict`；`id` 不存在 `404 not_found` | 必须 | 契约 §3.5, 裁定 A7 | TC-38, TC-39, TC-98 |
| FR-30 | 单任务累计输出上限 `limits.maxOutputBytes`（实现键名；默认 `1048576` = 1 MiB）：超限时只保留**尾部**上限字节并置 `truncated=true`；事件流中已推送的 `delta` **不回滚**，客户端以详情接口的 `output` 为准 | 必须 | 裁定 A5 | TC-100 |
| FR-31 | 客户端必须处理 `409 conflict` 与 `payload_too_large` 两类新增错误码并给出可读提示，不得因未知错误码崩溃 | 应该 | 契约 §0 | TC-98, TC-101 |

### 4.3 实时回传（SSE）

| ID | 需求 | 优先级 | 契约映射 | 验收方法 |
|---|---|---|---|---|
| FR-12 | `GET /api/v1/events?taskId={id}&fromSeq={n}` 提供 SSE：不带 `taskId` 订阅全部任务；事件类型 `task.created`(`task`)、`task.started`(`task`)、`task.output`(`delta`)、`task.finished`(`task`)、`task.progress`(`phase`,`note`)；每 15 s 发 `: ping` 心跳 | 必须 | 契约 §4 | TC-30, TC-31, TC-43 |

| FR-20 | 增量输出必须能在客户端按序拼接为完整 `output`；`data` 恒为单行 JSON，内部换行以 `\n` 转义，**不得因换行破坏 SSE 分帧** | 必须 | 契约 §4 | TC-31, TC-42 |

## 5. 非功能需求（NFR-xx）

### 5.1 安全（NFR-SEC）

| ID | 需求 | 量化指标 | 验收方法 |
|---|---|---|---|
| NFR-SEC-01 | 除 `/api/v1/health` 与 `/api/v1/pair/claim` 外的所有 `/api/v1/*` 必须校验 `Authorization: Bearer <token>`；缺失/错误返回 `401 unauthorized` | 未授权请求 100% 拒绝 | TC-70, TC-72 |

| NFR-SEC-07 | 禁止以 shell 字符串拼接方式调用子进程；prompt 中的引号、换行、中文、路径反斜杠必须安全传递 | 注入用例（含 `"` `&` `|` `%` 与换行）全部作为字面量 | TC-77 |

### 11.2 非功能需求（NFR-V2-*）

| 编号 | 需求 | 验收方法 |
|---|---|---|
| NFR-V2-SEC-01 | 网关 HTTP 只绑 `127.0.0.1`；`host=0.0.0.0` 时 v2 relay 必须拒绝启动 | 判据 C + 网关负向测试 |
| NFR-V2-SEC-02 | 中继只存 `sha256(homeToken/deviceToken)`；日志中令牌/配对码/Authorization 脱敏（前 4 位 + `****`） | 代码审查 + 日志抽查 |
| NFR-V2-SEC-03 | 工作区路径必须 realpath 白名单校验，拒绝 `..`/符号链接/UNC → 403 `workspace_outside` | TC-V2-10 |
| NFR-V2-SEC-04 | `pair/open` 与 `relay/*` 只接受回环来源；home 经隧道只可访问契约 §3.4 的三条控制面路由 | 网关负向测试 + 中继路由白名单测试 |
| NFR-V2-SEC-05 | 镜像源（真实 `%USERPROFILE%\.dsh`）**只读**：网关不得写入用户真实 home | TC-V2-21（含阴性对照） |
| NFR-V2-SEC-06 | 手机端**不提供**自签证书信任开关（仅系统默认信任链，与 FR-15/O8 一致）；release 不得放开明文 HTTP | Android 侧检查（`network_security_config.xml` 无用户 CA、release 不放行明文） |
| NFR-V2-PERF-01 | 单条 `chunk` ≤ 256 KiB；单流缓冲 ≤ 1 MiB（超出 `abort: overflow`）；单连接并发流 ≤ 64 | 中继测试；`too_many_streams`/`overflow` 用例 |
| NFR-V2-PERF-02 | 手机端常驻的会话消息数与渲染项数都必须**有界**：滑动窗口上限 600 条、单页 60 条、LazyColumn 只渲染可见项；上拉加载更早时**不得**自动回滚到底部，用户离开底部后由「回到最新」显式回到底部 | TC-V2-28（窗口有界单测：capacity=10 时窗口恒为 10）；TC-V2-29（手动验收：加载更早后视口不跳） |
| NFR-V2-AVAIL-01 | 心跳：`ping` 无 `pong` 判死链；**`timeoutMs` 必须显著大于 `intervalMs`**（建议 3×），否则健康连接会被误杀 | 中继心跳回归 + E2E 判据 E 稳定性 |
| NFR-V2-AVAIL-02 | 网关运行时目录与镜像源**物理隔离**；网关自有 home 首次启动物化 `profiles/sdk` 不依赖公网 | 部署手册 §8 验证命令 + `POST /api/v2/tasks` 202 |
| NFR-V2-COMPAT-01 | v1 API（`/api/v1/*`）与既有 9 项自检不得回归；`dsh.binPath` 等 v1 配置键行为保持 | `scripts/selftest.ps1` + 网关既有测试全绿 |
| NFR-V2-MAINT-01 | 所有 PC 侧脚本：UTF-8 带 BOM、Windows PowerShell 5.1 可解析（无 PS7-only 语法）、`netstat`/实测命令可复现 | TC-V2-22（`check-scripts.ps1`） |
| NFR-V2-MAINT-02 | 跨网络验收必须有可重复的一键脚本（判据 A~E 逐条 PASS/FAIL + 真实输出 + JSON 报告落 `.runtime\acceptance\`） | `scripts/e2e-crossnetwork.ps1` |

### 11.3 范围外（明确不做）

- 手机**不能**续聊电脑端正在使用的桌面会话（DSH 有意设计，契约 §7.1）；
- 网关重启后**不能**接管之前由它驱动的手机任务会话（SDK 协议限制，`runtime_gone`）；
- 中继**不**提供多租户、配额、审计日志等企业特性；不落盘会话内容；
- 本轮**不**做公网实机验证（无公网 VPS），公网部分一律标注 `> 待验证（需公网 VPS）`。

  > `docs/05-运维/中继部署手册.md` §9.2 与 `docs/04-验收/验收报告.md`。**域名形态**（有域名 + 正式证书）
