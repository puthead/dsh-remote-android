## 1. 分支与提交规范

### 1.1 分支模型（轻量 GitHub Flow）

| 分支 | 用途 | 命名 | 生命周期 |
|---|---|---|---|
| `main` | 可交付主干，任何提交都应处于可构建、可验收状态 | `main` | 长期 |
| `feat/<topic>` | 新功能 | `feat/android-task-detail` | 合并即删 |
| `fix/<topic>` | 缺陷修复 | `fix/sse-seq-dedup` | 合并即删 |
| `docs/<topic>` | 仅文档变更 | `docs/deploy-manual` | 合并即删 |
| `chore/<topic>` | 构建、依赖、脚本 | `chore/pin-agp-8.7.3` | 合并即删 |

| 规则 | 内容 |
|---|---|
| B1 | 禁止直接向 `main` 推送功能提交；一律走分支 + 评审 |
| B2 | 分支粒度＝一个可独立验收的改动；跨端改动（改契约同时改两端）允许一个大分支，但必须在 PR 描述中列出三处落点 |
| B3 | 接口变更分支命名建议带契约字样：`feat/api-v2-add-files`，且 PR 必须同时包含契约、FR、TC 三处更新 |
| B4 | 合并前必须：本地构建通过 + 相关用例通过 + 无 TODO 遗留（除带 issue 编号的显式 TODO） |

### 1.2 提交信息（Conventional Commits）

```text
<type>(<scope>): <subject>

<body：为什么这么改，而非改了什么>

<footer：Closes #12 / BREAKING CHANGE: ...>
```

| type | 用途 | 触发版本号 |
|---|---|---|
| `feat` | 新功能 | minor |
| `fix` | 缺陷修复 | patch |
| `docs` | 仅文档 | 无 |
| `refactor` | 不改变外部行为的重构 | 无 |
| `perf` | 性能优化 | patch |
| `test` | 测试代码 | 无 |
| `chore` | 构建/依赖/脚本/配置 | 无 |
| `revert` | 回滚 | 视情况 |

| scope | 含义 |
|---|---|
| `gateway` | PC 网关 `tools/dsh-remote` |
| `android` | Android 客户端 |
| `api` | 接口契约 `docs/01-设计/API契约.md` |
| `docs` | 其他文档 |
| `scripts` | PowerShell 安装/运维脚本 |
| `repo` | 仓库级配置（.gitignore、编辑器配置等） |

| 规则 | 内容 |
|---|---|
| C1 | `subject` 用中文或英文均可，但**同一 PR 内保持一致**；不超过 60 字符；不以句号结尾 |
| C2 | 禁止 `update`、`fix bug`、`修改` 这类无信息量 subject |
| C3 | 破坏性变更必须在 footer 写 `BREAKING CHANGE:` 并说明迁移方式 |
| C4 | 涉及接口的提交必须写 `Refs: docs/01-设计/API契约.md §X` |
| C5 | 一个提交只做一件事：文档与代码尽量分开提交，便于回溯 |

**示例**

```text
feat(gateway): 支持 SSE fromSeq 断点续传

环形缓冲保留最近 2000 条事件，客户端带 fromSeq 或 Last-Event-ID 时补发缺失事件。
超出窗口时返回窗口内事件，客户端改用任务详情快照兜底。

Refs: docs/01-设计/API契约.md §4
Closes #23
```

### 1.3 变更影响面登记（必须）

任何改动完成后，必须判断是否触发下列登记动作：

| 改了什么 | 必须同步 |
|---|---|
| 接口路径/字段/状态/错误码 | ①契约递增 `X-Api-Version` ②FR 表 ③TC 表 ④[变更记录](../06-项目管理/变更记录.md) |
| 需求新增/删除 | ①需求规格说明书 ②验收标准矩阵 ③TC 表 |
| 目录结构或构建方式 | ①本文 §3 ②[部署手册](../05-运维/部署手册.md) |
| 依赖或工具链版本 | ①本文 §7 ②本文 §8 版本号 ③变更记录 |

## 2. 代码风格

### 2.1 Kotlin / Android

| 规则 | 内容 |
|---|---|
| K1 | 遵循 **Kotlin 官方代码风格**（`kotlin.code.style=official`，4 空格缩进） |
| K2 | 遵循 **Android Kotlin Style Guide**：Compose 可组合函数用 `PascalCase`，参数默认值靠后 |
| K3 | 包名固定 `com.deepseek.dshremote`；分包 `data/`、`ui/`、`ui/theme/` |
| K4 | 禁止在主线程做网络/IO/JSON 大解析；一律 `Dispatchers.IO` |
| K5 | UI 层不直接持有 OkHttp；只能通过 `data/TaskRepository` |
| K6 | Compose 状态必须单向数据流（`StateFlow` → `collectAsStateWithLifecycle`），禁止在 Composable 内启动网络请求 |
| K7 | 可空性优先：能不用 `!!` 就不用；必须用时在上一行注释原因 |
| K8 | 字符串资源与用户可见文案放 `res/values/strings.xml`（中文为默认值），代码中不硬编码长文案 |
| K9 | 行宽 ≤ 120 字符；单文件 ≤ 500 行为宜，超出应拆分 |
| K10 | 构建版本组合固定：AGP `8.7.3` / Gradle `8.9` / Kotlin `2.0.21` / Compose BOM `2024.09.00` / `compileSdk 34` / `minSdk 26` / `targetSdk 34`；升级须走变更记录 |

### 2.2 Node.js / 网关（ESLint 语义，无第三方运行时依赖）

| 规则 | 内容 |
|---|---|
| N1 | ESM（`.mjs`），`"type":"module"`；禁止 `require` |
| N2 | 缩进 2 空格；语句必带分号；字符串统一单引号（模板串例外） |
| N3 | 变量：`const` 优先，只有真需要重赋值才 `let`；**禁止 `var`** |
| N4 | 相等比较一律 `===` / `!==`（除与 `null` 比较可 `== null` 同时覆盖 `undefined`） |
| N5 | 未使用变量/参数必须清理（`_` 前缀表示有意忽略） |
| N6 | `async` 函数中的 `await` 不得遗漏；禁止「fire-and-forget」的 Promise 不带 `.catch` |
| N7 | 所有外部输入（HTTP body/query/header、子进程 stdout）必须先校验类型与范围 |
| N8 | 错误统一为 `{ error: { code, message } }`，`code` 必须取自契约 §0 枚举，禁止自造码 |
| N9 | 严禁 `child_process.exec` / `execSync`（走 shell）；只允许 `spawn` + argv 数组 |
| N10 | 文件写入必须原子：写临时文件 → `fs.rename`；日志追加用 `appendFile` |
| N11 | 每文件职责单一（routes / auth / queue / runner / events / store 分离） |
| N12 | 不得引入运行时第三方依赖；仅 Node 标准库（NFR-MAINT-01） |

### 2.3 PowerShell（脚本目录）

| 规则 | 内容 |
|---|---|
| P1 | 文件头必须有 `Set-StrictMode -Version Latest` 与 `$ErrorActionPreference='Stop'` |
| P2 | 路径拼接一律 `Join-Path`；不硬编码用户名；支持 `-Home` / `-DshRoot` 等参数覆盖 |
| P3 | 必须兼容 PowerShell 5.1 与 pwsh 7（避免仅在 7 上可用的语法） |
| P4 | 输出用中文，关键步骤打印「下一步命令」；失败必须非零退出码 |
| P5 | 幂等：重复执行不得破坏既有配置，覆盖前备份为 `.bak-<时间戳>` |
| P6 | 凭据文件写 UTF-8 **无 BOM**，写完立刻回读校验 |
| P7 | 脚本内**禁止**出现真实 API Key 或令牌明文 |

## 4. 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| Kotlin 类/接口 | `UpperCamelCase` | `TaskRepository`、`SseClient` |
| Kotlin 函数/属性 | `lowerCamelCase` | `submitTask()`、`fromSeq` |
| Kotlin 常量 | `UPPER_SNAKE_CASE` | `MAX_BACKOFF_MS` |
| Compose 可组合 | `PascalCase`，无返回值 | `TaskDetailScreen()` |
| JS 变量/函数 | `lowerCamelCase` | `handleClaim()`、`ringBuffer` |
| JS 常量 | `UPPER_SNAKE_CASE` | `RING_CAPACITY = 2000` |
| JS 私有模块内部 | 不导出即私有，不用 `_` 前缀 | `function hashToken()` |
| 文件名 | Kotlin: 与主类型同名；JS: `kebab-case` 或语义单名 | `TaskRepository.kt`、`events.mjs` |
| HTTP 字段 | `camelCase`（契约 §0 强制） | `taskId`、`reasoningEffort`、`createdAt` |
| 标识符值 | 见契约：任务 `task_xxx`、令牌 `tok_xxx`、令牌明文前缀 `dshr_` | `task_01J…`、`tok_7a1b…` |
| 分支 | `type/topic`，小写短横线 | `fix/sse-seq-dedup` |
| 环境变量 | `UPPER_SNAKE_CASE`，本项目统一前缀 `DSH_REMOTE_` | `DSH_REMOTE_PORT` |

**保留名禁止复用**：`DSH_HOME`（DSH 语义）、`token`（响应字段）不得用于其他含义。

## 5. 注释规范

| 规则 | 内容 |
|---|---|
| M1 | 注释解释**为什么**，不复述代码在做什么 |
| M2 | 公开函数/类必须有 KDoc/JSDoc 简述：职责、参数、返回、抛错；内部小函数可省 |
| M3 | 涉及安全决策处必须留注释并指向需求编号，例如令牌比较、限速、白名单判定 |
| M4 | 与契约相关的常量/字段必须注明来源，例如 `// 契约 §4：心跳间隔 15s` |
| M5 | TODO 格式：`// TODO(#issue): 具体待办`；无 issue 编号的 TODO 不允许合入 |
| M6 | 禁止提交被注释掉的死代码；不要「保留以备将来」 |
| M7 | 代码里不得写真实密钥、令牌、内网 IP、个人路径（用参数或配置） |

**示例**

```js
// 契约 §6.3：令牌只存 sha256，比较必须恒定时间，避免时序侧信道（NFR-SEC-02）
function verifyToken(presented, storedHash) {
  const presentedHash = sha256(presented);
  return timingSafeEqualHex(presentedHash, storedHash);
}
```

## 6. 接口与契约纪律

| 规则 | 内容 |
|---|---|
| A1 | `docs/01-设计/API契约.md` 是接口唯一事实来源；代码中的路径、字段名、状态值、错误码**逐字一致** |
| A2 | 改接口必须先改契约、递增 `X-Api-Version`，再改两端；禁止「先写代码后补文档」 |
| A3 | 禁止在客户端硬编码服务端应给出的信息（如服务器名、版本、工作区列表） |
| A4 | 时间字段一律 Unix 毫秒整数、以 `At` 结尾；不得混用 ISO 字符串 |
| A5 | 错误体统一 `{"error":{"code","message"}}`；`code` 只能取契约 §0 九种枚举值 |
| A6 | SSE `data` 必须单行 JSON（换行转义 `\n`）；禁止多行 JSON 破坏分帧 |
| A7 | 未知字段必须容忍（向前兼容）：两端解析都不得因新增字段报错 |

## 7. 依赖管理

| 规则 | 内容 |
|---|---|
| D1 | 网关：**零第三方运行时依赖**；`dependencies` 必须为空，测试仅用 `node:test`（NFR-MAINT-01） |
| D2 | Android：仅允许 `OkHttp`（含 SSE）、`org.json`、`DataStore Preferences`、Compose/AndroidX 官方件（契约 §7） |
| D3 | 仓库来源只允许 `google()` 与 `mavenCentral()`；禁止私有镜像或未审计仓库 |
| D4 | 版本集中管理：Android 用 `gradle/libs.versions.toml`；升级需在一个提交内完成并跑通 `assembleDebug` + `testDebugUnitTest` |
| D5 | 新增依赖必须回答三问（写入 PR 描述）：解决什么问题 / 能否用平台能力替代 / 体积与许可证是否可接受 |
| D6 | 禁止引入需要运行时下载模型/二进制的依赖（网关须离线可用） |
| D7 | 传递依赖的安全风险由引入方负责跟进；发现高危漏洞优先移除而非升版本硬扛 |

## 8. 版本号策略

### 8.1 三个版本号，互不混用

| 版本号 | 含义 | 递增规则 |
|---|---|---|
| `X-Api-Version`（契约版本） | 手机 ↔ 网关接口版本，当前 `1` | 破坏性接口变更 +1（字段改名/删除、状态机变更、错误码语义变更）；纯新增可选字段不递增 |
| 网关 `gatewayVersion` | PC 网关实现版本，`MAJOR.MINOR.PATCH` | 破坏性改 `MAJOR`，向下兼容新增改 `MINOR`，修复改 `PATCH` |
| App `versionName` / `versionCode` | Android 交付版本 | `versionName` 同步语义版本；`versionCode` 每次交付 +1（单调递增） |

### 8.2 兼容矩阵（必须维护）

| 网关版本 | 契约版本 | App 版本 | 兼容性 |
|---|---|---|---|
| 1.0.x | 1 | 1.0.x | 完全兼容 |
| 1.1.x | 1 | 1.0.x | 兼容（App 忽略未知字段，A7） |
| 2.0.x | 2 | 1.0.x | **不兼容**：`health.apiVersion` 不匹配时 App 必须提示升级并停止提交任务 |

> 待验证：`health` 的 `apiVersion` 与 `gatewayVersion` 组合校验是否需要网关侧强制拦截，实施后回填。

### 8.3 语义版本判定表

| 变更 | 递增位 |
|---|---|
| 新增可选请求字段 / 新增响应字段 / 新增事件类型 | `MINOR`（契约不递增） |
| 修改字段类型、改字段名、删除端点、改状态机、改错误码语义 | `MAJOR`（契约 +1） |
| 修复不改变接口的缺陷 | `PATCH` |
| 仅文档/注释/日志文案 | 不递增 |

## 9. 评审清单（Code Review Checklist）

评审者必须逐项勾选；任一项不通过即打回。

### 9.1 通用

| # | 检查项 |
|---|---|
| R-01 | 变更范围与 PR 描述一致，无夹带无关改动 |
| R-02 | 提交信息符合[Conventional Commits](#12-提交信息conventional-commits)，scope 正确 |
| R-03 | 无 `console.log`/`println` 调试残留；无被注释掉的死代码 |
| R-04 | 无真实密钥、令牌、内网地址、个人绝对路径入库 |
| R-05 | 文档同步已按[变更影响面登记](#13-变更影响面登记必须)执行 |

### 9.2 接口一致性

| # | 检查项 |
|---|---|
| R-06 | 路径 / 字段名 / 状态值 / 错误码与[API契约.md](../01-设计/API契约.md)逐字一致 |
| R-07 | 若是接口变更：契约已更新且 `X-Api-Version` 已递增，FR/TC 已同步 |
| R-08 | 时间字段为 Unix 毫秒、以 `At` 结尾；错误体为统一封套 |
| R-09 | SSE `data` 为单行 JSON，换行已转义，`seq` 全局单调递增 |
| R-10 | 未知字段容忍（新增字段不会让旧客户端崩溃） |

### 9.3 网关专项

## 10. 安全编码红线（违反即阻断合入）

| # | 红线 | 正确做法 | 需求 |
|---|---|---|---|
| L1 | **令牌不落日志**：不得把令牌、`Authorization` 头、API Key 写入日志/任务文件/异常信息/崩溃上报 | 日志只记 `tokenId`；异常信息只含 tokenId 与原因 | NFR-SEC-02, FR-26 |
| L2 | **令牌只存哈希**：服务端持久化只写 `sha256(token)`；明文仅在配对响应中出现一次 | 存储结构只含 `tokenHash` 与 `tokenId` | NFR-SEC-02 |
| L3 | **恒定时间比较**：令牌/配对码比较不得用 `===` 短路比较 | 用等价长度的恒定时间比较函数；长度不同也走完整比较路径 | NFR-SEC-02 |
| L4 | **禁止 shell 拼接**：不得用字符串拼命令后交给 shell | `spawn(cmd, [args])`；prompt 作为单个 argv 元素传递 | NFR-SEC-07 |
| L5 | **禁止 `eval` / `new Function` / 动态 import 用户输入** | 显式分支或查表 | NFR-SEC-07 |
| L6 | **输入必校验**：HTTP 入参先校验类型、长度、枚举范围再用 | 统一校验函数，失败返回 `bad_request` | 契约 §0 |
| L7 | **路径不得越界**：`workspace` 必须规范化后判定在白名单内（含子目录） | `realpath` + 前缀边界判定，拒绝 `..` 穿越 | NFR-SEC-06 |
| L8 | **外网禁止明文**：部署与文档不得建议裸端口映射 | 只推荐 Tailscale / frp+TLS / Cloudflare Tunnel | NFR-SEC-05 |
| L9 | **App 令牌私有存储** | DataStore Preferences，禁止外部存储与日志 | NFR-SEC-08 |
| L10 | **凭据文件不入库**：`.credentials.yaml`、`.runtime/**`、`local.properties` 必须在忽略清单 | 示例文件只写占位值 | NFR-SEC-02 |
| L11 | **限速不可绕过**：限速计数基于真实来源 IP，XFF 仅在可信代理后启用 | 默认不信任 `X-Forwarded-For` | NFR-SEC-04 |
| L12 | **交付物如实声明**：APK 为 debug 签名自用包，README 与文档必须写明 | 不得宣称正式签名/可公开发布 | NFR-SEC-09 |
