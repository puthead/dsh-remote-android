# 修复报告：「工作区目录下的文件夹要都可以访问，当前存在越界问题」

> 任务来源：用户诉求原话（m00120）「工作区目录下的文件夹要都可以访问，当前存在越界问题」。
> 涉及仓库：`D:\Workspace\dsh_android`（PC 网关 `tools/dsh-remote` + Android 端 `android/`）。
> 报告日期：2026-10-15。所有命令与输出均为本机实测；鉴权用已有设备凭据完成，密钥内容不入档。

## 1. 根因

**一句话**：网关 `resolveTarget()` 的第 3 道「词法包含」检查，拿**默认工作区**的根去装**另一个白名单工作区**里的绝对路径，必然失败 → 403 `workspace_outside`；手机端当时**只发 `path`、不发 `?workspace=`**，于是永远落到默认工作区，白名单里配了也没用。修复前现场看到的两句文案（文件树空白 + 底部报错）都是这一条引起的。

### 证据链（文件:行 → 触发条件 → 错误文案）

| 环节 | 位置 | 说明 |
|---|---|---|
| ① 手机不发 `workspace` | `android/.../data/api/DshApiV2.kt`（修复前无 `workspace` 形参） | 工作区请求只有绝对 `path` |
| ② 网关回落默认工作区 | `tools/dsh-remote/lib/http.mjs:914-928` `workspaceContext()` | `?workspace=` 缺失时用 `defaultWorkspace`，实测 `C:\Users\Administrator\dsh-workspace` |
| ③ 词法包含必然失败 | `tools/dsh-remote/lib/workspace-fs.mjs:182-184`（修复前 :113） | `isWithin('D:\Workspace\插件', 'C:\Users\Administrator\dsh-workspace')` = false |
| ④ 抛错 | `tools/dsh-remote/lib/workspace-fs.mjs:184` | `路径越界（不在工作区内）：D:\Workspace\插件`，code `workspace_outside` |
| ⑤ 界面翻译 | `android/.../ui/vm/ErrorMessages.kt:60-61` | 用户看到 `（路径在工作区之外，已拒绝访问：请从工作区目录树里进入）` |
| ⑥ 假象 | `android/.../ui/screens/WorkspaceScreen.kt:376-379`（修复前） | 文件页只按 `entries.isEmpty()` 画「这个目录是空的（或未加载）。」→ 403 被画成"空目录" |

**逻辑证明**：`candidate` 是绝对路径，只有在 `requestPath` 本身为绝对路径时才可能出现；相对路径拼接不可能产出它 —— 所以问题一定出在"workspace 上下文"这一维，而不是路径本身。

### 不是根因的（已排除）

- **非 ASCII 编码**：两个 config 的 `workspaceAllowlist` 里 `D:\Workspace\插件` 的真实字节是 `443a5c576f726b73706163655ce68f92e4bbb6`（合法 UTF-8，19 字节），`论文` 是 `…e8aebae69687`。手机侧 `URLEncoder.encode(value,"UTF-8")` 产出 `D%3A%5C…%E6%8F%92%E4%BB%B6`，网关 `URLSearchParams.get` 能正确解回。
- **`http.mjs` 的 query 解析**：无二次编码/误解码。
- **`MAX_DEPTH=4` / `MAX_ENTRIES=2000`**：只影响一次列多深，不影响"进不去"（手机是逐层进入，`depth=1`）。

### 顺带查出的第二、第三个独立缺陷（同一句"文件夹进不去"背后的另外两张脸）

1. **junction/符号链接目录永远列不到下一层**：修复前 `listDirectory` 只在 `dirent.isDirectory()` 为真时下钻，而 Windows 上 junction 的 dirent **不报** `isDirectory()`。本仓库实测有 3063 个重解析点（3060 个逃逸到 `C:\Users\Administrator\AppData\Local\npm-cache\…`），例如 `D:\Workspace\dsh_android\.runtime\acceptance\profiles\node_modules\accepts`。
2. **读写共用同一道 realpath 检查**：修复前连**读**也要求 realpath 落在白名单内，于是"工作区里指向外部的链接目录"读也被拒，错误码还和"真越界"混用 `workspace_outside`，用户无法区分。
