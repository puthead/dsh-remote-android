> **本轮（v2.7.1，2026-10-15）修的是用户真机截图里那条「刷新失败：电脑离线：中继隧道未连接，请检查中继地址或等待重连（PC 网关或隧道未连接）」**（用户原话 m00003）。
> 定位结论：**电脑、网关、中继同时都是好的**（中继 `/health` `{"ok":true,"relayVersion":"2.0.1"}`、网关 `relay.connected=true reconnects=0 lastError=null`、桌面端 DSH 在 `127.0.0.1:19387` 监听），
> 坏的是**手机自己那条隧道**——中继日志里这台真机每 20s~4min 掉一次（绝大多数关闭原因 `code=1006 reason=socket error`，该真机三天 55 次下线里 40 次是这个取值），重连区间很宽：复核实测为 **8.9s / 13.4s / 13.9s / 17.6s**，而 50 个可配对样本里只有 **20% 能在 12s 内**、**26% 能在 20s 内**回来，另有 5 次掉线后 1 小时~8 小时没重连（多半是应用被杀/手机休眠）；
> 用户那次下拉刷新正好落在重连窗口里，而「没有活句柄」被直接报成了"电脑离线"。
> 修复全在客户端（**服务端零改动，不需要重启网关**）：① 主读操作撞上抖动先等隧道回来（≤**20s**，初版 12s 经独立核验后上调）再原样重试一次；② `waitOnline` 每秒复检"句柄真的开着"，不再拿过期状态冒充可用；③ 在线判定补上 `relay.isConnected`（消除"假在线"）；④ 请求成功后立刻清离线态；⑤ **冷启动第一次就连不上时也挂自愈探测**（原来要求"之前在线过"，冷启动必不成立 ⇒ 界面会一直挂"电脑离线"直到手动刷新）。
> 实测（模拟器 `emulator-5554` → 公网中继 `wss://123.207.183.237:9443` → 真实网关 8787 → 桌面端 DSH）：用 `iptables` 只黑洞中继 IP 制造黑障，黑障中刷新读到 `隧道暂不可用，等待重连（最多 20000ms）后自动重试一次`，网络恢复后**不点任何按钮**、一个等待窗口内读到 `隧道已恢复，重试成功`，副标题自动回到 `已发起 1 · 默认电脑端执行`（离线标记消失）；另在**黑障进行中冷启动**（验证第 ⑤ 条）也无需点按即自行恢复，全程无 `FATAL EXCEPTION`。
> 单测 **506 用例 / 0 失败 / 0 错误 / 1 跳过（45 个测试类）**；详见 `docs/06-项目管理/变更记录.md` §16 与 `android/BUILD.md` §5。

### 3.1 现在就能用（2026-10-13 起的生产形态，无需域名）

中继已在云服务器上以 systemd 常驻（v2.0.1）：**手机要填的中继地址 = `wss://123.207.183.237:9443`**
（`relay-pair.ps1` 打印的是它的完整隧道路径 `wss://123.207.183.237:9443/api/v2/tunnel/device`，
两者都行 —— App 会自动剥掉路径再补 `/api/v2/tunnel/device`）。


### 3.2 派任务时选权限档（v2.1.0 新增）

「会话」页 → 新建任务对话框里多了一行**权限档**按钮：

| 档位 | 含义 | 默认 |
|---|---|---|
| **仅当前工作区** | 任务只能读写所选工作区，越界读写被沙箱拒绝 | ✅ 默认选中 |
| **全部权限** | 任务可读写这台电脑上**任意路径**（桌面、其它盘、用户目录），且不再逐条确认 | 需手动点选，并显示风险提示 |

- 实现：网关把该档位翻译成 DSH 子进程的环境变量 `DSH_PERMISSION_MODE`
  （`workspace` → `workspace-write`，`full` → `danger-full-access`），因为 DSH 侧没有"权限"命令行参数。
- 契约：`POST /api/v2/tasks` / `POST /api/v1/tasks` 请求体新增可选字段 `access`（`"workspace"` | `"full"`）；
  202/201 响应会回执实际档位；**未知取值一律 `400`**，绝不"猜"成高权限；不带该字段的旧客户端 = 默认档。
- 公网实测（2026-10-13，手机模拟器经 `wss://123.207.183.237:9443`）：
  `full` 任务把文件写到工作区之外 `C:\Users\Administrator\dsh-workspace\access-probe\probe-full.txt`（内容 `full-ok`）；
  `workspace` 任务写同一位置被拒：`Error: [sandbox: file access denied under workspace-write mode]`，文件不存在。
  证据：`.runtime/acceptance/permission-access-20261013-220041/RESULT.md`。
- **v2.5.0 起该档位只对「仅在手机上执行」的任务生效**：新建任务**默认落在电脑端**，此时请求体不带 `access`
  （客户端 `accessForHost()` 保证），权限跟随电脑端 DSH 进程自己的 `DSH_PERMISSION_MODE`（全局、非每会话）。
  想在电脑端指定权限档：目前没有这个能力，只能改电脑端 DSH 自己的设置。合同见契约 §7.6。

### 已知限制（必须知道的四条）

1. ~~**手机不能续聊电脑端正在使用的那个会话** —— DSH preset realm 的设计限制（契约 §7.1）~~ —— **该条自 v2.4.0 起已被推翻**
   （v2.0 当时的口径，保留作历史）。现在手机经电脑端 runtime 的回环 Remote RPC 通道**可以**续聊电脑端原生会话：
   `POST /api/v2/sessions/{id}/turns` → `202 {driver:"desktop", source:"computer"}`，轮次收束后 `resumable:true`，可反复接手；
   只有该会话**此刻正被电脑端自己占用**时才返回 `409 session_busy`。详见契约 §7.4/§7.5 与 `docs/04-验收/验收报告.md` §13。
2. **网关重启后，之前由它驱动的手机任务会话不可再续**（SDK 协议限制）：`writable:false, writableReason:"runtime_gone"`；
   `POST /abort` 因 SDK 无 cancel 只能杀进程，杀完同样不可续（`resumable:false`），需新建任务。
   （注意：这条只对**手机任务**（`source:"phone"`）成立；电脑端会话（`source:"computer"`）重启后仍可接手。）
3. **电脑端通道上手机做不到的事（v2.5.0 的边界；第 ② 条自 v2.6.0 起已解除）**：① 无法为电脑端会话**指定权限档**（见 §3.2 末尾）；
   ~~② 电脑端 DSH 处于 `approval/policy: ask` 时，若某轮触发审批，**手机无法代答**~~ → **自 v2.6.0 起手机可以直接应答**：
   电脑端那一轮卡住时，手机会收到 `approval.asked` 并在详情页弹出审批卡（**接管输入区**），点「允许一次」/「拒绝」即真的放行或拦住
   （`GET /api/v2/approvals`、`POST /api/v2/approvals/{eventId}`，契约 §7.7）；**提问**（`ask_user_question`）同样可以选答案提交。
   两条限制如实保留：**手机与电脑端 UI 是竞答关系**（谁先答谁生效，后到者拿 `not_found`），
   **TTL 15 分钟只是网关侧记账**（过期后电脑端那一轮仍挂着）。
4. **公网部署已实机验证（2026-10-13）**：真实 VPS（Ubuntu 26.04，安全组放行 22 + 9443，80 留给证书 http-01）上以
   Let's Encrypt **IP 地址证书**跑通 `wss://123.207.183.237:9443`，`scripts/deploy-relay.ps1` 五处缺陷已修并通过
   `-DryRun` 复验；手机侧（`scripts/tests/phone-sim.mjs` 手机模拟器）经公网完成配对、任务派发与续聊，探针 **12/12**；
   用户真机（PGT-AN00）也已在 9443 上配对成功。
   证据：`docs/05-运维/中继部署手册.md` §9.2、`docs/04-验收/验收报告.md` §10、`.runtime/acceptance/relay-public-e2e-*`、
   `.runtime/acceptance/relay-port-9443-20261013-221430/RESULT.md`。
   仍**未实测**的只有「有域名 + 正式 DNS 证书」形态。
