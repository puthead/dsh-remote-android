## 1. 真相表

### 1.1 先说结论（推翻任务书里的一个假设）

任务书假设「29 条里有子代理会话在刷屏」。**实测否证**：那 29 条**没有一条是子代理**，全是 `origin=user`、`delegationDepth=0`、无 `parentSession` 的真实顶层会话（里面「调用 ask_user_question 询问发布环境」「测试越界写入审批重试」「越界写入并重试提权」等是**人手动开的测试会话**，标题像派生而已）。

真正的缺陷有两条，都是**判据太弱**而不是"数量算错"：

1. 缺省列表把**1 条 fork** 当成顶层会话显示（`session-b64b78d8-5490-4d8c-936a-09a82c4c9616`），因为旧判据只看 `origin`，而这条 header 里根本没有 `origin` 字段 ⇒ 兜底成 `user` 放行。所以基线是 **30 条**，用户截图顶部却是 **29**（桌面端口径）。
2. 判据过窄带来**结构性风险**：真实 home 里有 **108 条** `origin=subagent` 的会话，只要任何一次 header 字段缺失/格式演进（旧版桌面端、镜像到旧 home、第三方写入），`origin` 一旦缺失就会被当顶层会话整批泄露。手机端 `JsonV2.kt` 又把网关缺失的 origin 默认成 `"user"`，两层叠加，防不住。

## 3. 新判据 + 与 DSH 桌面端的对照

### 3.1 新判据（单一真相源，Node 与 Kotlin 同源）

`tools/dsh-remote/lib/dsh-home.mjs:79-133` 新增三个导出函数（纯函数、零依赖）：

```js
export function inferSessionOrigin(header)      // {'user'|'subagent'}：显式 origin 优先；缺失时按 isDerivedSession 推断；**绝不默认 user**
export function delegationDepthOf(header)       // number：非负整数才认，缺失/异常一律 0
export function isSubagentSession(header)       // origin==='subagent' || delegationDepth>0
export function isDerivedSession(header)        // isSubagentSession(header) || parentSession 非空
```

判据优先级与失败方向：

1. `origin` 有非空字符串 ⇒ **以它为准**（做 trim + toLowerCase 容错，兼容 `"SUBAGENT"`/`" subagent "`）；
2. `origin` 缺失/空串 ⇒ `delegationDepth > 0` 判派生；
3. 前两条都不成立但有 `parentSession` ⇒ **判派生**（fork / seeded 副本 / 子代理三条路径共用此字段）。

第 3 条是刻意选的失败方向：**宁可少显示一条，也不刷屏**。这类会话在 `?include=subagent|all` 时全部可见，详情端点也仍按 id 可达，所以严格化不会造成数据不可达。

### 3.2 与 DSH 桌面端做法的对照

桌面端权威做法（asar 源码取证，副本在 `.probe/x/`）：

- `/dsh/node_modules/@deepseek-ai/dsh-client-ui-workspace/lib/client.js:357-367` `sessionVisible()` 第一句就是 `if (session.origin === "subagent") return false;`——**子代理会话永远不是侧边栏的一行**，6 个调用点全部因此过滤（含内容搜索 `:562-578`）。
- 侧边栏是**扁平顶层、无缩进**（`client.js:469` 注释 "every session as a top-level row"）；唯一父子耦合是 fork 排序 `placeFork`（`:330-338`，插到父行正上方，非缩进）。
- 谓词的产生源头在 `/dsh/node_modules/@deepseek-ai/dsh-subagent/lib/index.js:470-481` `childSessionMeta()`：`{parentSession, isSeeded, origin:"subagent", delegationDepth: childDepth}`——**子代理会话一定带 origin**，顶层会话则不写 origin。
- 桌面端给子会话的入口是**父会话页头的后代目录 + 右侧栏 tab**（`dsh-client-ui-subagent/lib/client.js:602-614` `SubagentCatalogAction`、`:620-647` 面包屑、`:963-974` 挂载点），并明确写「子会话在这里不渲染任何东西」。
- 桌面端**没有**"显示子代理"开关；`session/list` 也**没有任何过滤参数**（`dsh-api-session-controller/lib/index.js:2948-2956` 的 `list(_request)` 刻意不用参数；`lib/types/list.js:296-302` 仍把 `parentSessionId`/`origin` 下发），**过滤纯在客户端**。
- 另一个独立信号：`/dsh/node_modules/@deepseek-ai/dsh-workspace-changes/lib/index.js:985-986` `return origin === "subagent" || (delegationDepth ?? 0) > 0 ? void 0 : cwd;`——即 `delegationDepth` 在别处也参与判定，我把两条信号合并正是照此。

| 维度 | DSH 桌面端 | 本实现（手机端） | 差异说明 |
|---|---|---|---|
| 判定谓词 | `origin === 'subagent'`（+ 别处 `delegationDepth>0`） | `isDerivedSession` = `origin==='subagent' \|\| depth>0 \|\| parentSession 非空` | **多认 `parentSession`**：桌面端 `placeFork` 明确让 fork 保持可见（排到父行上方），手机端是窄屏平铺列表、没有"插到父行上方"的视觉手段，父与 fork 同标题并列会被当成刷屏，故手机端把 fork 也折叠 |
| 数据在哪过滤 | 纯客户端（Host `session/list` 全量下发） | **服务端过滤**（`SessionMirror.list`）+ 手机端二次判据 | 手机走设备令牌 + 公网中继，少传 109 条派生会话能省带宽与流量；且离线缓存不会把派生会话翻出来 |
| 默认可见性 | 子代理**永久隐藏**，无开关 | 默认隐藏，保留「含子代理」开关（契约 §4.2） | 契约要求保留开关，用户显式要时能看到 |

| 用词 | 中文文案是「**子智能体**」（`dsh-client-ui-subagent/lib/client.js:835` 起；全 asar 里「子代理」**0 命中**） | 用户可见文案已统一为「子智能体」 | 本次特意对齐（用户原话里说的是"子智能体"） |
